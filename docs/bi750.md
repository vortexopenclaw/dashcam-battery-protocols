# BlackboxMyCar BI-750

Status: hardware-observed telemetry on firmware **1.6**. The protocol uses `ITSC` framing and unsigned big-endian measurement fields. It is distinct from BlackVue `43 06` and Cellink Neo+ `@@` framing.

## GATT transport

| Role | UUID |
|---|---|
| Service | `49535343-fe7d-4ae5-8fa9-9fafd205e455` |
| Client to battery | `49535343-8841-43f4-a8d4-ecbe34729bb3` |
| Battery to client | `49535343-1e4d-4bd9-ba61-23c647249616` |

Discover properties, subscribe to the battery-to-client characteristic and use the write mode supported by the selected writer. The upstream ESP32 implementation uses write with response. Advertisement prefixes such as `Bi750` are discovery hints, not identities for public logging; omit device-specific suffixes.

## Requests and response framing

```text
49 54 53 43 00 00 WW 00
```

`49 54 53 43` is ASCII `ITSC`; `WW` selects the reply type. These are eight-byte telemetry requests. No response-checksum rule is established by the dataset.

| Word | Purpose | Observed response size |
|---|---|---|
| `32` | Firmware/model | 17 bytes |
| `33` | Charge, temperature, raw mode | 16 bytes |
| `34` | Input/output electrical values | 16 bytes |
| `35` | Time estimates and configured capacity | 16 bytes |

Request `32` once, then cycle `33`, `34`, `35`. A tested client sent one request per second, so each measurement group refreshed about every three seconds. This is a tested polling strategy, not a guaranteed rate limit. Timestamp each group independently; three replies are not an atomic snapshot.

The upstream reference also describes production-identification word `3A`; its payload can identify the device. Configuration-command payloads remain undocumented here. The `ITSC` header, word and word-specific length guide reassembly; the final trailer is unverified.

## Field layouts

Offsets are zero-based from the complete response. Bytes 0–3 are `ITSC`, bytes 4–5 are a source-described device-ID field, and byte 6 is the word. Omit device-ID values from public examples; ours use zero placeholders.

| Word | Offset | Bytes | Field | Decode |
|---|---|---|---|---|
| `32` | 7 | 1 | Firmware | Decimal tenths: `16` → `1.6` |
| `32` | 8–10 | 3 | Build date | Source-described metadata; omit actual values from public captures |
| `32` | 11 | 5 | Model | ASCII model name |
| `33` | 7 | 1 | Charge | Percent |
| `33` | 8 | 1 | Temperature | °C; positive values hardware-corroborated |
| `33` | 9 | 1 | Raw mode | Preserve raw code; partial interpretation below |
| `33` | 10 | 1 | Settings mask | Source-derived; not interpreted here |
| `34` | 7 | 2 | Input voltage | Big-endian / 1000, V |
| `34` | 9 | 2 | Input current | Big-endian / 1000, A |
| `34` | 11 | 2 | Output voltage | Big-endian / 1000, V |
| `34` | 13 | 2 | Output current | Big-endian / 1000, A |
| `35` | 7 | 2 | Time to full | Big-endian minutes |
| `35` | 9 | 2 | Discharge runtime estimate | Big-endian minutes |
| `35` | 11 | 2 | Reported configured capacity | Big-endian mAh |

Trailer offset is 16 on word `32`, and 15 on the three 16-byte telemetry replies. Reserved bytes remain uninterpreted.

## Mode interpretation

Upstream maps 1 to charging and 0 to discharging; a conservative client can show 0 as charging stopped until electrical fields establish output activity. Raw mode 4 also occurs during charging, but its complete meaning is unresolved. Preserve the raw code and independent input/output measurements for unknown modes. Negative-temperature encoding, expansion reporting and complete protection modes remain unknown. Capacity is configured, not measured health.
