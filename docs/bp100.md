# VIOFO BP100

Protocol revision: **BP100 V39**, corroborated by hardware responses. Manufacturer implementation supplies the field map; BP60 is a different product and is not included.

## Transport and initialization

| Role | UUID |
| --- | --- |
| Service | `c0a12213-64b5-6e57-3299-aab3c4d1eaf0` |
| Client to battery | `c0a12213-143a-7ed7-5291-a3bfc5c1da0f` |
| Battery to client | `c0a12213-2455-fe56-3866-5ad3e4f112b0` |

Observed writer: write + write without response; reader: read + notify. Subscribe through standard CCCD `2902`, then GET_MODE `41`. Do not periodically read the command-response stream. Require BP100 family, exact transport, positive firmware and application mode `16` before queries `01`–`04`. Boot mode `1` and unknown modes do not unlock status.

Native initialization may query/set a bound UID. The status sequence above avoids changing binding. Binding enforcement can vary by firmware; private UID contents are not required to document framing.

## Framing and CRC correction

```text
AA 55 AA 55 LL LL CC 00 XX XX 00 00 [payload]
```

LE16 payload length at complete-frame offset 4, command at 6, LE16 CRC at 8, payload at 12. Total length is payload+12. Reassemble split/coalesced notifications. Outgoing CRC16/XMODEM uses polynomial `0x1021`, initial 0, no reflection/final XOR, over the complete frame with CRC bytes 8–9 zeroed.

| Query | Command | Empty request |
| --- | --- | --- |
| Mode/firmware | `41` | `AA 55 AA 55 00 00 41 00 06 5C 00 00` |
| Charge/state | `01` | `AA 55 AA 55 00 00 01 00 16 36 00 00` |
| Temperature | `02` | `AA 55 AA 55 00 00 02 00 F6 F8 00 00` |
| Input/time to full | `03` | `AA 55 AA 55 00 00 03 00 56 BD 00 00` |
| Output/runtime | `04` | `AA 55 AA 55 00 00 04 00 17 75 00 00` |

**Receive policy:** the native battery session explicitly disables incoming CRC validation, despite the parser default enabling it. Retain outgoing CRC and identity/length/plausibility gates rather than requiring replies to pass the request CRC algorithm. Incoming checksum semantics are unverified. Expected payload lengths: `41`:5, `01`:2, `02`:4, `03`/`04`:8. [Source provenance](sources.md#viofo-bp100).

## Payload-relative field map

Add 12 to these offsets for complete-frame positions. Multibyte values are little-endian.

| Command | Field | Decode |
| --- | --- | --- |
| `41` | Firmware | Unsigned LE32 p0 |
| `41` | Application mode | p4; observed16 |
| `01` | Percent | p0 & `0x7f` |
| `01` | Charging flag | p0 bit7; unset maps to Discharging |
| `01` | Extension flag | p1 nonzero, source-derived presence boolean, not count |
| `02` | Core temperature | p0/10 + (p1 & `0x7f`); negate if p1 bit7 |
| `02` | Board temperature | Same at p2/p3; source-derived; native dashboard uses core |
| `03` | Input voltage/current | p0/10+p1 V; p2/10+p3 A |
| `04` | Output voltage/current | p0/10+p1 V; p2/100+p3 A |
| `03`/`04` | timeA | LE16 p4; unknown semantics |
| `03` | Base minutes to full | LE16 p6 |
| `04` | Base runtime minutes | LE16 p6 |

Calculate watts as V×A; preserve each group's timestamp. Native UI can scale timeB using a configured extension count; publish the unscaled base estimate until configuration semantics are independently verified. Capacity is not transmitted by these queries, and a boolean extension flag cannot establish exact count, usable energy or health. Negative temperatures and extension detection remain source-derived/unexercised. Validate percent, temperature and electrical plausibility before publishing values.

## Additional command identifiers

Source-derived identifiers, not fully documented write recipes: `05` set power-off, `06` get power-off, `07` set bound UID, `08` get bound UID, `09` unbind UID, `0A` set buzzer, `0B` get buzzer, `42` boot mode, `43` OTA. Payload/acknowledgement and persistence details require further specification before a complete implementation. These do not inherit the empty measurement-request format automatically.
