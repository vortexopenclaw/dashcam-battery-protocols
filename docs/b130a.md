# BlackVue B-130A

Status: hardware-observed telemetry on firmware **1.61**, returned identity **B-130A**. The [shared wire protocol](blackvue-legacy.md) applies, with big-endian input/output voltage at offsets 23 and 25 instead of classic offsets 11 and 12.

## Implement a client

1. Recognize advertisement prefix `130A` even without a leading `B`.
2. Discover `FFF0`, subscribe to `FFF1`, use the no-response writer `FFF2`.
3. Send `43 06 00 52 17`; accept the returned `B-130A` model and integer firmware 161. The source's `B-130X` name is a separate identity.
4. Send `43 06 00 51 14`; revision 161 status is 29 bytes, with 24 payload bytes. Input/output voltages are BE16 at offsets 23/25 divided by 10, instead of the classic bytes 11/12. Decode other [shared fields](blackvue-legacy.md#status-reply-51) normally.

[B-130X firmware1.61](b130x.md) now has its own hardware-observed profile. Other revisions remain source-derived. Extended flags/protection mapping and incoming checksum remain unresolved. Reset frame/identity state for each new connection. Capacity is configured; runtime is the raw estimate rather than manufacturer UI averaging.

On B-130A firmware 1.61, status `51` can report zero output current while charging (state 1 and positive input voltage/current). That does not establish that an attached load is consuming no power. Show output power as unavailable in that condition, retaining the reported zero in the underlying data. With input off, state 3 and positive output current, volts × amps produces the discharge output watts. A brief state-0/zero-current interval can occur during the charging-to-discharge transition; it is not proof of an empty battery or permanently disabled output.
